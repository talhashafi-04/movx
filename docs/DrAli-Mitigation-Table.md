
| Weakness | Recommended solution |
|---|---|
| Independent reference measurements are not secured. Without them, the students cannot establish whether the displayed elbow-extension values are correct. | Arrange access to an appropriate biomechanics laboratory, validated multi-camera measurement setup, or suitable paired dataset. The product can remain single-camera even when validation uses additional equipment. |
| The measurement definition is ambiguous. "Change between Arm Horizontal and Ball Release" does not fully specify the calculation. | Have a biomechanics expert define the anatomical angle, event boundaries, treatment of intervening movement and hyperextension, and calculation from the angle trajectory. |
| Single-camera accuracy is unproven. A plausible 3D skeleton does not guarantee accurate biomechanics. | Compare simple 2D, temporally filtered and temporal 3D baselines against reference measurements. Establish the capture conditions under which measurements are reliable. |
| "Uncertainty-aware" is not operationally defined. Pose confidence is not equivalent to measurement accuracy. | Validate uncertainty against actual measurement errors. Report accepted-case accuracy alongside acceptance rate, and test whether unreliable recordings are appropriately rejected. |
| The dataset plan is missing. General pose and cricket-action datasets do not necessarily provide the required biomechanical labels. | Use public datasets for component development, supplemented by a bounded collection of reference-measured bowling deliveries. Separate training, calibration and testing by bowler. |
| Novelty is not established. Closely related low-cost markerless bowling-analysis research already exists. | Compare directly with the closest published systems. Frame the proposed contribution around validated single-camera measurement, supported capture conditions and calibrated rejection—not merely pose detection or angle calculation. |
| Too many difficult components are presented as committed features. | Limit the initial product to one delivery per clip, declared bowling types and tested camera modes. Select one main pose/temporal pipeline. Defer long-session segmentation and broad device support. |
| Automatic event detection introduces additional measurement error. Ball Release cannot simply be assumed from wrist movement. | Validate event timing against independently annotated recordings. Initially provide automatic suggestions with manual correction, and measure event errors separately from angle errors. |
| Evaluation criteria are insufficiently specified. | Measure extension error in degrees, systematic bias, large-error cases, uncertainty calibration, rejection rate and processing time. Agree acceptable error and useful acceptance thresholds with domain input before final testing. |
| Stakeholder involvement is asserted rather than demonstrated. | Obtain concrete workflow feedback from coaches or an academy, and measurement guidance from a biomechanics expert. Document consent and video-handling arrangements. |
| Some CCP selections are broadly-defined rather than complex. Unknown implementation parameters also do not automatically establish ill-defined requirements. | Retain honest classifications. Emphasise the strongest dimensions: analytical depth, domain knowledge and interdependent error propagation. Do not inflate every selection. |
| Deployment and failure contingencies are unclear. | Specify whether inference runs on the phone or a server. Define supported recording conditions. If validated numerical screening proves infeasible, formally revise the scope to clearly labelled visual analysis—not unvalidated legality screening. |

**Priority before defence:** secure a credible reference-measurement route, define the measurement precisely, narrow the scope, and run a small technical feasibility experiment alongside the required interface PoC.
